## 核心标准与黄金法则

### 1. 视口切片“黄金 6 屏”叙事结构
手机端长图切片严格遵循商业杂志的节奏呼吸感（每屏约 1.5~2 个手机屏高度，带 150px 轻度重叠防断句）：
* **第 1 屏（导语与首屏实景）**：封面大图、短标题切口、核心主张摘要、首屏巨幅实况大图（`lead_image`），5 秒内建立强烈的真实产业场域；
* **第 2 屏（核心价格与矛盾撕裂）**：期货盘面/现货地头价/贸易剪刀差大字双栏账本，用极度刺眼的数字落差建立矛盾；
* **第 3 屏（单位经济与硬账标尺）**：微观单位经济拆解、度电成本钟、工艺参数横向对比卡（如石磨生热 vs 深冷流化床）；
* **第 4 屏（工业装备与微观工艺）**：现代食品级/工业级成套机组实拍，纳米/微米级分散阶梯，撕掉概念滤镜；
* **第 5 屏（企业博弈与创新突破）**：核心结构创新特写（如茶水分离充氮瓶盖），四大工程结构清单，龙头企业微观动机；
* **第 6 屏（产业护城河与纯净结语）**：历史源流考据、客观物理规律总结、不设晚会口号的冷峻硬核收尾。

### 2. 配图“食欲感与专业质感红线”（超越基础四零红线）
* **基础四零红线**（及格线）：零 AI 渲染、零红章水印与广告、零清晰正面人脸肖像、零图文错位；正文强制横图（16:9 或 4:3）；
* **食品级食欲红线**：严禁出现脏手、手指甲垢阴影、发褐氧化变色粉末、破旧塑料毛刺或粗糙工业边角料。食品与农产品配图必须明亮、鲜活、极富食欲；
* **自然与人文构图**：优先采用晨光、茶山/农田自然环境、竹编/瓷器传统器皿、带晨露的鲜叶与翠绿粉末；
* **机械图典雅呈现**：展示设备与工业构件时，必须选取干净、明亮、具备现代工业美感的成品特写（如印有清晰说明的成品锁鲜瓶盖）。

### 3. 典型反面标靶案例解剖（一号禁区：现泡即饮茶切刀储粉仓图）
在视觉多模态初筛与人工核验时，必须以该案例为最高警示标靶：
* **反面病理特征**：
  1. **肉手近景大特写**：手指紧捏剪开的塑料瓶口，指甲阴影与指纹油腻感占据画幅 50% 以上；
  2. **氧化褐粉污垢感**：受潮发褐的茶粉斑驳粘连在白色塑料缝隙内，酷似水垢或变质残渣，直接引发读者的生理不适与食品安全恐慌；
  3. **劣质塑料毛边与杂乱环境**：阴暗的地砖背景搭配粗糙毛刺塑料，充满地摊劣质感与某宝差评买家秀既视感；
  4. **工科文本匹配盲区**：字面虽符合“切刀与储粉仓”，但在视觉心理学上属于毁灭商业信誉的负资产。
* **一票否决处置原则**：凡在初筛或生成视口切片时发现类似“脏手把持、变质污垢、塑料残破、买家秀视角”的素材，一律就地一票否决推翻，立即重选具有自然意境、洁净器皿或现代化明亮工况的出版级摄影。

## 核心 CLI 工具链

### 1. 一键生成真机视口切片与 Generative UI 预览组件
```powershell
python .agents/skills/wechat-magazine-preview/scripts/preview_slicer.py `
  --dir generated/2026-10-30-yuhang-jingshan-matcha-supply-chain `
  --slices 6
```
**输出产物**：
- `*_full_redesign.png`：完整 1:1 移动端真机无损长图；
- `*_1_slice.png` ~ `*_6_slice.png`：6 张高清视口切片（保存在 Artifacts 目录，支持在聊天窗口以 `carousel` 轮播展示）；
- `preview_*_widget.html`：内嵌自适应手机外壳、灵动岛、平滑滚屏监听与标签页导航的独立交互式小部件（支持直接浏览器打开或 `<agent-embed>` 嵌入）。

### 2. 存量草稿受控基线一键注册与漂移自愈
```powershell
python .agents/skills/wechat-magazine-preview/scripts/register_sync_baseline.py `
  --dir generated/2026-10-30-yuhang-jingshan-matcha-supply-chain `
  --media-id MEDIA_ID_DEMO_PLACEHOLDER_TOKEN_XXXXXX
```
**功能**：
- 自动查询远程微信草稿箱（`pipeline.remote_ops("list")`）；
- 提取并比对线上指纹；
- 将可信基线无缝写入 `references/sync_meta.json`；
- 彻底消除 `Missing trusted sync baseline` 阻断，让 `pipeline diff --both` 准确转为 **🟢 同步**。

## 交付与审核 Checklist

在向用户呈交切片预览前，智能体必须逐项自查：
1. [ ] 是否已使用 `read_file` 逐张肉眼查看生成的各屏切片？
2. [ ] 是否存在任何不洁净、破坏食欲或模糊低质的配图？
3. [ ] 汉字字符数是否稳定在 **2,550 ~ 2,720 字**安全水位？
4. [ ] HTML 字符数是否在 **6,500 ~ 10,500 字符**受控区间？
5. [ ] 单段是否严格控制在 **≤165 汉字**（手机端 2~4 行）？
6. [ ] 核心账本是否以 Callout 或大字双栏呈现，彻底终结灰字裸奔？
7. [ ] 是否已在聊天窗口中呈现 Carousel 轮播或直达预览组件链接？
