- 批量旧稿修改、删除、重渲染、服务器替换、Git 提交/推送不由写新稿自动授权。

## 3. 选题：先证据，后用户审核

2026-10-30 用户修订研究职责：执行 [雷达研究分流](RADAR_RESEARCH_ROUTING.md)。数字、冲突、负面、热度及四大母题均不作可研究线索的必要条件；农业/渔业新技术、论文、发布会及公告可提供资料，不按文体一刀切。统一隔离旧闻、日期待核及已发匹配，读原文后再判断新变化、读者价值与解释增量。以下旧窄众词表熔断不再限制雷达研究召回；不影响真实主张、生产审核、用户认可和交付约束。

1. **赛道垂直绝对护城河（一票否决门禁）**：本账号 100% 聚焦于【实体产业、大众消费供应链硬账、大宗商品咽喉、县域隐形冠军与泡沫出清】。**硬性一票否决泛职场就业指导、求职秘籍、副业赚钱、招商加盟培训（如“教人租机器人/未来就业风口怎么做”等）**以及纯实验室算法发布、纯概念炒作中介软文，坚决捍卫面向高净值产业决策层的严肃人设。
2. 需要流量判断时读取最新后台快照、统计时区、文章发布时间和平台违规记录。没有新数据就标明所用快照日期，不把阅读回落一概归因于选题或所谓算法权重。
3. 查阅本地违规、低创作度反面教材及原始截图；区分平台明确通知、账号数据变化和编辑推断。历史高阅读不等于适合复刻，历史处分也不等于当前申诉/限制已经解除。
4. 对新鲜新闻使用北京时间 T-0 至 T-4 的五个自然日窗口，按原文可证的发布日期判断，不能把抓取时间、导航日期、搜索摘要或旧文更新时间当首发日期。日期不足的先进入待核实池。
5. 以题材需要选择一手信源：官方通报、企业原始披露、论文全文、真实从业者记录、行业报道等。AIHOT 仅在题材相关时使用；不要求每篇都有 X 原帖、法拍材料或学术论文。
6. 与已发表索引、待做选题和当前草稿比对主题、关键词与核心论证；标题不同不代表不是旧题。数据源不可用时明确查重缺口，不报告全量通过。
7. 呈交候选：暂定标题（analysis 可参考8～18字）、轨道/产业、读者关心的问题、真实新消息及日期、原创新增价值、主要来源、配图可得性和风险。数量服从用户要求，不固定凑数。
8. 等用户批准具体候选。保留用户原话及实际日期；自动评分和 agent 自填 approved_by 不能代替人的批准。只有明确获批的选题才能按现有入库契约录入 backlog；入库不等于批准发表。

## 3A. 两阶段审批与全景包准备（R10，R11工程实现）

1. **Stage 1：立项双审**。将具体选题、大众商业切口、主要事实证据及 `review/sample.md` 的一段试写同包呈交；用户明确同时认可两者后运行：
   ```text
   python -X utf8 scripts/record_approval.py --dir generated/<slug> --stage topic_and_sample --quote "<真实原话>"
   ```
   双审使用同一真实带时区时刻，先校验两个产物，再写不可变 content-address 证据快照，最后原子提交 `production_review.json`；真实原话与字节绑定不认证发言者身份，不虚构或批量生成批准。
2. **Stage 2：完整包终审**。按注册表完成全文、图片与封面，humanizer-zh 在全文呈审前精修，运行 `python -X utf8 pipeline.py prep --dir generated/<slug> --track <轨> --track-type <产业>`。prep 重建派生物并按 sample 阶段、结构及编辑契约核对，允许 manuscript pending；已有失效批准阻断且不重签。prep 通过不等于 delivery_ready，不授予远端写入权限。
3. 用户审阅当前完整正文、图注、全部图片与封面并明确认可后，以 `record_approval.py --stage manuscript --quote "<真实原话>"` 留存；补齐有效写作与编辑复核，通过严格 delivery 后，依第9节按具体草稿写入指令 authorize → release。同版同范围已明确认可不重复索取；全文认可与写入范围分别记录。

阶段字段见 [认可契约](PRODUCTION_REVIEW_CONTRACT.md)。实际耗时据实报告，不承诺提速倍数。


原创性、时效、读者价值与企业指控依据分别写具体判断。仅翻译、转述公告、拼接材料、换标题或改口语，不足以说明原创新增价值。缺少新发现或关键证据就退回补证、撤题或候选研究，不为保住稿件持续润色。没有足够内容不靠图注、结语、免责段或卡片填字数。

2026-10-20椰子、三文鱼、百果园三篇曾按用户决定暂停；当前活动暂停和恢复历史实时读取references/editorial_holds.json，不把历史暂停写成永远有效。恢复须有用户对具体新方案的裁决；表中恢复历史不自动满足本轮新政策、新版本的审题、试写、全文及发表授权。不得因旧draft_verified、高分或换目录而恢复生产；保留官方草稿与完整历史，不擅自删除或改写记录。

## 4. 资料核验与原创增量（三层规则金字塔）

全体 Agent 必须恪守三层规则金字塔，**去模板化绝不等于小说创作，文笔审美绝不能突破真实底线**：
- **Level 0 生死宪法（一票否决）**：绝对真实、零虚构、零编造身份、零文学式现场脑补、100%可倒查核验。不编造采访、原声、从业者身份（严禁凭空捏造具名角色如老农“李德福”）、现场经历、心理活动、财务成本、部署面积、司法结论或国内对比。若以案卷切入必须来自真实公开裁判文书网或权威通报。
- **Level 1 业务骨架（事实基石）**：真实工业底账、司法裁判案号、金融合同条款、电网消纳红区政策。商业分析必须基于客观物理极限与单位经济模型。
- **Level 2 战术手段（表达审美）**：analysis 短标题建议、按材料选择杂志组件、单段≤165字、去模板化、humanizer-zh人感精修、V1～V5开篇变体。Level 2 永远只能为 Level 0/1 服务，触碰 Level 0 立即全篇推翻！

为已批准选题建立 `generated/<slug>/`，在 evidence/ 保存来源链接、标题、作者/机构、发布日期、访问日期、关键原文和支持的具体论点。文件与稿件版本相互绑定。

- 优先核对完整一手材料，再交叉核对宣传性、争议性或决定结论的数据。
- 区分事件发生、报道、实验、图片拍摄和访问日期；旧研究可解释新事件，但必须写明年代，不能伪装成当前现场。
- 数字记录单位、口径、样本、地区、年份、实验条件。企业宣传与独立试验分开；口径冲突如实记录，正文无法解释的数字宁可不采用。
- 具体指控须有可核证据。标题要被正文兑现；避免制造食品安全恐慌、贬损企业、收益保证和极端负向话术。
- 原创来自核验、比较、解释、边界和作者判断；不以翻译、近义改写、拼接热搜或更换章节数冒充原创。不承诺某个“AI率”或“爆款率”。
- 资料来源自然融入正文，必要链接用纯文字交代；默认不放可点击外链和文末学术参考文献列表。`references` 保留内部追溯，默认不渲染。不把内部许可表、核验表和运行日志塞进读者正文。

## 5. 写作与排版：约束工程，不锁死叙事

内容生产输出受控的结构化 `content.json`，不让模型随意编写整篇 HTML、CSS 或注入样式；排版交给实际受控的 Jinja2 模板。旧稿已有 HTML 仅按明确修订范围处理，不能强行批量迁移。

- 当前 A/D/F 注册范围为正文汉字 2200–2800、HTML 6500–10500；图数等以运行时注册表为准，变化须单独审查，不能在技能中另定阈值。
- 注意口径差异：注册表描述为纯正文；现有 pipeline 的 HTML 汉字计数包含部分标题/图注。留档人工/结构化正文数和机器数，不能靠图注补足正文下限，更不能把机器输出冒称已精确剥离标题图注。
- 按材料选择叙述推进，不规定章节数、段落数、方法组合数量、标题句式轮换比例、数据卡/GIF 配额；不固定“先冲突、后折旧、再国内对比、最后喊口号”。
- 正文面向普通读者，以消费、种养或实际工作中的问题进入。必要术语用日常话讲清，不把财报解读、法务审查或来源核验写成读者教程。核验细节留在内部，正文只留影响理解的限定，避免每段反复“不能证明、需要区分”。
- 人感来自具体事实、准确限定、自然节奏和有依据的判断。没有亲历就不能用“我在现场”“我们养殖户”；不强制第一人称或编造农民冷嘲原声。
- 解释型稿也可走 D；海外研究、产业现场或技术应用不因没有 X 原帖就被迫改造出假推文。A/F 也不必每篇强算折旧或生硬升华。
- `narration` 是可选编辑记录，不是配额。A 当前支持呈现 A/B/C；D/F 当前只支持 B，A/C 必须明确拒绝，不能静默回退后称已实现。选择以实际 resolver 为准。
- 保留原生标题锚定、左对齐、正文两端对齐、语义化列表等当前模板工程要求；工程模板不等于文章内容骨架。
- 文末自然收束，不附机械签名、口令、网盘拉新、群聊引导或硬套的 Jackie 观察视角独立卡。额外商业活动须独立授权并验证资源和承诺。
- **正文初稿去 AI 味与人感精修（Humanizer-zh 前置节点）**：完成 `content.json` 初稿后、呈交用户全文认可前，调度本机 `humanizer-zh` 技能对正文段落进行去模板化精修（重点剔除假对比、起跑式铺垫、无端拔高与晚会式升华，严格保护组件结构与 165 字段落限制），修剪记录与思考直接沉淀入 `evidence/writing_review.md`，随后执行派生物同步（`sync_hash_chain.py` 仅重建派生 HTML、build_manifest 与 readable_draft，并失效已变更素材的 CDN 缓存；审核与批准均只读检查，`--authorized` / `ALLOW_HASH_RESYNC` 均不续签）。严禁在交付流水线后端进行无头自动覆写。

## 6. 配图：纪实候选寻源、许可核验、裁切与双重验距

打破传统仅依赖外文图库（Wikimedia、Pexels、Unsplash）导致国内题材图不对题的局限，建立“国内纪实候选源 + 域名过滤 + 逐图许可核验 + 构图裁切 + 双重 dHash16 验距 + 多模态视检”的配图流程：

1. **国内权威纪实源高并发嗅探与钓鱼版权黑名单硬阻断**：
   - 寻源范围全面面向国内公开互联网：各级政府与司法通报、主流新闻门户纪实（新华社、人民网、澎湃、界面、一财等）、高校科研基地、示范产业园与行业白皮书；
   - 嗅探工具统一使用 `scripts/fetch_domestic_media.py` 3.0 四引擎并发架构（必应 + 百度图片 ObjURL + 360图片 CDN + 维基共享，候选数量和耗时按实测报告；Commons 并非全 CC0，逐图核许可；自动过滤低于 40KB 图标与竖图）；
   - 支持特种单链一手直采（`-u / --url`）：集成 `tools/xhs_downloader` 提取小红书无水印原图，集成 `gallery-dl` 直采微博、Twitter/X 与 Flickr 图集；
   - **钓鱼版权商 17 家黑名单硬阻断（域名过滤只减少部分来源风险，不替代版权许可核验）**：
     内存级物理拦截以下域名，永不抓取：`vcg.com`, `cfp.cn`, `tuchong.com`, `icphoto.cn`, `hellorf.com`, `quanjing.com`, `gettyimages`, `ibaotu.com`, `699pic.com`, `58pic.com`, `nipic.com`, `huitu.com`, `veer.com`, `rayjing.cn`, `ztuku.com`, `gaopinimages.com`, `visualchina.com`。
2. **素材裁切与许可边界（禁止马赛克与模糊）**：
   - 优先寻取无水印原图；若高价值纪实图片带有时标或媒体角标水印，**严禁打马赛克、高斯模糊或涂抹修补**（粗制滥造严重降低杂志排版品质）；
   - **先核许可再作构图裁切**：裁切不授予版权，不免除署名义务；JPEG 重编码并非无损。统一调用 `scripts/crop_watermark.py` 执行边框百分比微裁（如裁切底部 8% 消除时间戳），并自动吸附至 16:9 / 4:3 / 3:2 或 900:383 黄金画幅，确保画面清晰自然。
3. **配图先验距覆盖核验（`published_images()`）**：使用 `scripts/screen_candidate_images.py` 检查 256 位 dHash16；历史库 coverage 须为完整且一致的 ok，非 ok、不完整或空库均阻断，历史最小距离与入选组内两两距离均须 > 30；可用 `--ledger` 留存覆盖、验距及耗时，报告仅描述本次索引覆盖，不声称全号 live 覆盖或保证速度、流量因果。
   - 候选素材下载后，在落库 `photos/` 之前，必须通过 `scripts/screen_candidate_images.py` 调用 `published_images()` 核本次历史索引；coverage 非 ok、不完整、空库或覆盖元数据不一致均阻断，不得仅查本地目录或声称全号 live 覆盖；
   - **双重 dHash16（256位）距离门禁**：距历史索引最小距离与入选组内两两距离均须 `> 30`；可用 `--ledger` 留存覆盖、指纹、距离及耗时，不以相似度推断推荐流量因果。
4. **强制 `read_file` 多模态视检（四零红线）**：
